# unreal-myth-bench

언리얼에 도는 성능 통설 아홉 개를 실제로 재보는 벤치마크입니다.
데모 영상을 만드는 대신 누가 클론해도 같은 숫자가 나오는 리포트를 남깁니다.

> 초기 단계입니다. UE 프로젝트 골격까지 올라갔고 러너와 시나리오는 아직입니다.

## 주제

| 통설 | 실제로 재는 것 |
|---|---|
| Tick을 쓰지 마라 | 등록된 Tick 수와 작업량에 따른 게임 스레드 시간 |
| Blueprint Event Tick이 비싸다 | Lyra에서 CMC · PlayerController · BP Tick 비교 |
| Blueprint는 C++보다 느리다 | VM 경유 횟수별 격차, Development와 Shipping 양쪽 |
| Cast를 쓰면 다 로드된다 | 런타임 비용과 에셋 로드 의존성을 따로 |
| Cast와 Implements는 성능이 같다 | 호출당 비용과 참조 그래프 |
| ChildActorComponent를 쓰지 마라 | 배치 수와 생성 빈도별 스폰 시간, 메모리 |
| GetAllActorsOfClass는 느리다 | 액터 수와 호출 빈도 중 어느 쪽이 지배적인지 |
| 정확한 주기는 TimerManager로 | 실행 간격 분포와 deadline 초과율 |
| Paper2D는 죽은 기능이다 | 5.8 지원 범위와 드로우콜 |

항목은 2026 언리얼 페스트 "모범 사례에 대한 오해와 진실" 트랙을 들으며 던진 질문에서
나왔습니다. 강연 결론을 받아 적기보다 그 주장이 어디까지 참인지 곡선으로 확인하려고 합니다.

액터 수를 10, 100, 1,000, 10,000으로 늘려가며 잽니다. 통설은 보통 특정 구간에서만 맞습니다.

## 에셋

엔진 내장 에셋만 씁니다. `/Engine/BasicShapes/`, `/Engine/EngineMeshes/` 같은 경로를
**참조만 하고 `.uasset` 파일은 레포에 넣지 않습니다.** 그래서 이 레포가 재배포하는
남의 저작물은 0바이트입니다. UE 5.8만 있으면 클론해서 바로 돌아갑니다.

규칙 전문은 [기획 문서의 에셋 정책](docs/00-plan.md#에셋-정책)에 있습니다.
